# 功能文档索引

本文件是项目功能说明的统一入口。每次新增功能，或者改变已有功能的玩家可见行为、操作方式、数据流或架构时，必须同步更新对应 Markdown；没有对应文档时，应在 `docs/` 中新建并登记到本索引。

## 核心功能

| 功能 | 简介 | 文档 |
|---|---|---|
| 应用与昼夜循环 | `AppRoot` 持有唯一 `PlayerData`，`GameFlow` 在白天、夜晚和结局间切换 | `architecture.md`、`game_flow.md` |
| 共享数据模型 | 玩家数据、昼夜结算及配方、药水、材料、关卡、剧情物品等静态定义 | `data_model.md` |
| 关卡接入约定 | 白天关卡与运行时之间的接口和组织方式 | `level_contract.md` |
| 双世界系统 | 雪莉／卢卡与双世界关卡机制 | `../day/systems/dual_world/README.md` |
| 白天探索 | 玩家、相机、战斗、采集、交互、谜题、传送与正式关卡 | 对应功能目录；新增或调整时在 `docs/` 补充专题文档 |
| 夜间经营 | 炼药、顾客、商店、经济、对话与夜间 UI | 对应功能目录；新增或调整时在 `docs/` 补充专题文档 |
| 菜单与转场 | 主菜单、天空表现、菜单 UI 和进入游戏的转场 | `../menu/`；新增或调整时在 `docs/` 补充专题文档 |
| 小游戏 | 相对独立的小游戏模块 | `../minigames/`；各小游戏应拥有自己的功能说明 |

## 更新要求

- 功能实现与文档必须在同一次修改中完成。
- 简介至少应说明功能目的、玩家如何触发或操作、主要场景／脚本位置、关键数据流，以及相关测试。
- 修改已有功能时优先更新原文档，避免为同一功能创建多份相互矛盾的说明。
- 删除或重命名功能文档时同步更新本索引。
